# Signing and notarization

Without Apple credentials, builds are signed ad-hoc and macOS blocks them at first launch. Once
the five GitHub secrets below exist, every `v*` tag publishes a Developer ID signed and
notarized DMG, with no change to the code or the workflows.

Requirement: a paid [Apple Developer Program](https://developer.apple.com/programs/)
membership. Only the Account Holder can create Developer ID certificates.

## 1. Create the Developer ID Application certificate

1. Open Keychain Access: `/System/Library/CoreServices/Applications/Keychain Access.app`.
2. Menu **Keychain Access > Certificate Assistant > Request a Certificate From a Certificate
   Authority…**. Enter your e-mail address and a name, leave "CA Email Address" empty, choose
   **Saved to disk**, and save the `.certSigningRequest` file.
3. Open <https://developer.apple.com/account/resources/certificates/list> and click **+**.
4. Under "Software", choose **Developer ID Application**, then **Continue**.
5. Profile type: **G2 Sub-CA**. Upload the request from step 2, then **Continue**.
6. **Download** the `.cer` file and double-click it to add it to the **login** keychain.
7. Check that the identity is usable. The command must list a "Developer ID Application" line:

   ```bash
   security find-identity -v -p codesigning
   ```

   If it lists nothing, install the "Developer ID - G2" intermediate certificate from
   <https://www.apple.com/certificateauthority/> and run the command again.

## 2. Export the certificate as `.p12`

1. In Keychain Access, select the **login** keychain, tab **My Certificates**.
2. Right-click **Developer ID Application: …** (it must unfold to show a private key), then
   **Export…**.
3. Format **Personal Information Exchange (.p12)**, file name `DeveloperID.p12`, in
   `Downloads`.
4. Set a strong, new password generated by a password manager, and keep the file and the
   password there. macOS may then ask for your login password to allow the export.

## 3. Create the App Store Connect API key (for `notarytool`)

1. Open <https://appstoreconnect.apple.com/access/integrations/api>
   (**Users and Access > Integrations > App Store Connect API**).
2. Tab **Team Keys** (individual keys do not work with `notarytool`). The first time, click
   **Request Access** and accept the terms.
3. Click **+**. Name: `ClamStop notarization`. Access: **Developer**. Click **Generate**.
4. Note the **Issuer ID** (above the table) and the **Key ID** (in the key row).
5. **Download** `AuthKey_<Key ID>.p8` to `Downloads`. It can be downloaded only once: keep it
   in the password manager too.

## 4. Add the GitHub secrets

Run each command from any folder. Those without a pipe or `<` prompt for the value, so it does
not stay in the shell history.

1. The certificate:

   ```bash
   base64 -i ~/Downloads/DeveloperID.p12 | gh secret set MACOS_CERTIFICATE_P12_BASE64 --repo ChanOJ/ClamStop
   ```

2. Its password (paste it at the prompt):

   ```bash
   gh secret set MACOS_CERTIFICATE_PASSWORD --repo ChanOJ/ClamStop
   ```

3. The API key. The pattern matches the single `AuthKey_*.p8` file in `Downloads`; if several
   exist, replace it with the exact file name:

   ```bash
   base64 -i ~/Downloads/AuthKey_*.p8 | gh secret set NOTARY_API_KEY_P8_BASE64 --repo ChanOJ/ClamStop
   ```

4. The key ID (paste it at the prompt):

   ```bash
   gh secret set NOTARY_API_KEY_ID --repo ChanOJ/ClamStop
   ```

5. The issuer ID (paste it at the prompt):

   ```bash
   gh secret set NOTARY_API_ISSUER_ID --repo ChanOJ/ClamStop
   ```

6. Check that the five names are listed:

   ```bash
   gh secret list --repo ChanOJ/ClamStop
   ```

7. Once the password manager holds both files, delete `DeveloperID.p12`, the `.p8` file and the
   certificate signing request from `Downloads`.

## 5. Dry run

Builds, signs, notarizes and writes the appcast without publishing anything. It needs the five
secrets above and `SPARKLE_ED_PRIVATE_KEY` ([updates.md](updates.md)), with the public key
committed.

1. Start it:

   ```bash
   gh workflow run release.yml --repo ChanOJ/ClamStop --ref main
   ```

2. Find the run ID:

   ```bash
   gh run list --repo ChanOJ/ClamStop --workflow release.yml --limit 1
   ```

3. Once it is green, download the `ClamStop-dry-run` artifact into a new folder:

   ```bash
   gh run download --repo ChanOJ/ClamStop --name ClamStop-dry-run --dir ~/Downloads/ClamStop-dry-run
   ```

4. Check the DMG. The first command must succeed, the second answer
   `source=Notarized Developer ID`:

   ```bash
   xcrun stapler validate ~/Downloads/ClamStop-dry-run/ClamStop-0.0.0.dmg
   ```

   ```bash
   spctl -a -vv -t open --context context:primary-signature ~/Downloads/ClamStop-dry-run/ClamStop-0.0.0.dmg
   ```

## 6. Publish a signed release

1. From an up-to-date `main`, create the tag:

   ```bash
   git tag v1.0.0
   ```

2. Push it:

   ```bash
   git push origin v1.0.0
   ```

3. Follow the **Release** workflow under the repository's **Actions** tab. The release notes
   state whether the build is notarized. A tag with a suffix (`v1.0.0-rc.1`) publishes a
   pre-release, useful for a first trial of the secrets.
4. Download the DMG from the release in a browser, install it, and check that it opens without a
   Gatekeeper warning. This command must answer `source=Notarized Developer ID`:

   ```bash
   spctl --assess --type execute --verbose=2 /Applications/ClamStop.app
   ```

## Troubleshooting

| Symptom | Cause and fix |
| --- | --- |
| "set both MACOS_CERTIFICATE…" or "set all of NOTARY…" | A secret is missing: add it (section 4). |
| "no valid 'Developer ID Application' identity" | The `.p12` has no private key, or another certificate type: export again (section 2). |
| `security import` fails on the password | `MACOS_CERTIFICATE_PASSWORD` does not match the `.p12`. |
| notarytool answers 401 | Wrong key ID or issuer ID, or an individual key instead of a team key. |
| Status `Invalid` | The workflow log prints Apple's report with the file and the reason. |

After fixing a secret, use **Re-run failed jobs** on the workflow run.

The certificate expires after five years. Releases notarized before that keep working; create a
new certificate (sections 1, 2 and 4) for the next ones. If a key or the certificate leaks,
revoke it from the same Apple pages.

## Signing on a Mac (optional)

With the certificate in the login keychain, the same scripts sign locally. Replace the identity
with the line printed by `security find-identity`:

```bash
SIGN_IDENTITY="Developer ID Application: Your Name (TEAMID1234)" scripts/build-app.sh
```
